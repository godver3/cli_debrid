### cli_debrid is now called Clyde
- New name and logo across the app: header, browser tab, favicon, home-screen icon, onboarding, help pages and notifications
- Only the name changed. Updating needs nothing from you: your settings, database, logs, environment variables and folder paths all stay the same
- The Docker image is still `godver3/cli_debrid`, and every build is also published as `godver3/clyde` with the same tags. Either name works
- The default logo is the new Clyde icon. The **Color Icon** and **Plex-Inspired** logos are still in Settings → UI Settings
- New box set and Adaptive List collection posters use the Clyde icon. Posters already in Plex are left as they are
- For the AI assistant (MCP) connection, new setups show the server name `clyde`. Existing connections keep working
- The home page terminal still says `user@cli_debrid:~$`, as a nod to where it all started

### New
- **New movies are searched on their release day**
  - A movie is first searched at midnight at the start of its release date (plus **Movie Airtime Offset**). It used to wait until midnight at the end of that day, when releases were usually already out
  - If nothing is found that day, it's searched again every hour. Those retries don't count toward the wake limit, so a movie can't be blacklisted any sooner than before
  - Shows are unchanged: episodes still go by their air time
- **The Upgrade Hub no longer misses NZB releases**
  - Scans used to see only each indexer's newest 1,000 releases at the moment they ran, so most of a day's releases were never checked
  - Now, while the Upgrade Hub scan is on, a new **Upgrade Hub NZB feed sync** task reads what's new on each Newznab indexer every hour, usually one or two API calls each, and keeps the releases that match your library for 90 days. Scans check that history
  - Movie releases the indexer tags with an IMDb ID are matched by ID, so a different film's release can't be mistaken for yours. TV releases are matched by title, season and episode, because indexers sometimes tag them with the wrong ID
  - More indexers are read. The old request sent an empty search, which indexers such as AltHUB, NinjaCentral and NZBPlanet refuse, so only some indexers returned anything. Clyde now asks the standard way, and if an indexer refuses it, tries the other common forms. An indexer that refuses all of them is named in the log
- **Release Age setting**
  - Sets which newly collected items get the upgrade window, by how recently they were released (default 7 days). It was fixed at 7 days before

### Changed
- **All upgrade settings are on the Upgrade Hub**
  - A new **Upgrading** group on the hub's Settings tab holds turning upgrading on, the release age, the upgrade window, the score improvement needed, the score to stop at, the extra search after release, and removing the old copy
  - Settings → Scraping and Settings → Queues & Upgrades link there instead. Your existing values are kept
- **Cache badges work beyond Real-Debrid**
  - TorBox users see whether a candidate is cached, from TorBox's own cache check. Real-Debrid still uses Phalanx
  - Auto-queue queues cached candidates first and skips ones reported not cached, unless you accept uncached results
- **The Upgrading queue no longer holds up other queues**
  - It runs every 5 minutes and searches for at most about 2 minutes per run. Items it doesn't reach go first on the next run, and each item is still searched at most once an hour
- **Scheduled Upgrade Hub scans run in the background**, so they don't delay other scheduled tasks

### Fixes
- **4K upgrades of the same release were skipped**
  - A result whose name was 95% similar to the current file was treated as the same file, so "Movie.2025.2160p.WEB-DL-GROUP" never replaced "Movie.2025.1080p.WEB-DL-GROUP". Now only the same release is skipped
- **Saving Settings could turn upgrading off**
  - The Settings page switched upgrading off whenever its checkbox wasn't on the page
- **The Upgrade Hub applied debrid-only filters to NZB releases**
  - A filter-out term set to **Debrid** (or **NZB**) in a version applied to every release in the hub, so a debrid-only `WEB-DL` rule hid most NZB upgrades. Each term now only applies to its own source, as it already did when scraping
- **Obfuscated files looked like big upgrades**
  - A file with a random name such as `b8ccc80d….mkv` was scored by that name, which says nothing about its quality, so almost any release looked like a large upgrade. The hub now uses the release name the file was grabbed as, and shows it in the Current column
- **A subtitle site that was down slowed every search**
  - Podnapisi's site has stopped answering. Every subtitle search still tried it, waited, and logged a long error, then tried again for the next item
  - A provider whose site can't be reached is now paused for an hour, and one whose searches time out for 10 minutes, as Clyde already did for providers that refuse requests
  - The result no longer says "nothing passed the match threshold" for a provider that never answered. It names that provider as paused and says why
- **OpenSubtitles.org login errors blamed your password**
  - The old **OpenSubtitles.org** provider refuses logins that work on OpenSubtitles.com, but Clyde said to check your username and password. It now says to use **OpenSubtitles.com** instead
- **Manually assigning an NZB season pack only assigned one episode**
  - Picking **Seasons** or the whole show on the manual assign page and giving it an NZB ignored that choice, so the pack was tracked as a single item and only one episode got its file. Each episode of the picked seasons now gets its own item, for an NZB link and an uploaded `.nzb` file alike
- **Country versions missed NZB releases named without the country**
  - For a show like **The Traitors (IN)**, a release with no country or language in its name is treated as the original show and skipped. Some of its season packs are named just `The.Traitors.S02…`, so they were never picked up
  - When the NZB indexer files such a release under this show's own IMDb ID, it's now accepted. A release whose name says another country is still skipped
