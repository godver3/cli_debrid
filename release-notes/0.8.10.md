### New
- **Upgrade Hub searches with your own scrapers**
  - Each scan searches your configured scrapers (Torrentio, Jackett, Prowlarr, Newznab and so on) for a batch of library items, 50 by default
  - Items never checked go first, then the ones checked longest ago, so a daily scan works through the whole library over time. A better release that appears months after an item was collected is now found
  - **Scan Limit** doesn't narrow this search: it still limits the Zilean and NZB checks, but the scraper search picks from the whole library
  - Zilean is no longer required. Zilean and the NZB indexer feed are optional extra sources, and **Bulk Sources → None** turns them off
  - New **Search With My Scrapers** and **Items Searched Per Scan** settings on the hub's Settings tab
- **Search Recent Releases button on the Upgrade Hub**
  - Searches your scrapers for a better release of every collected item released in the last N days. N defaults to your Release Age setting
  - Shows how many movies and episodes that is before it starts, then runs as a normal scan, so better releases appear in the results to queue as usual
  - Not limited by Items Searched Per Scan, and works with Search With My Scrapers turned off. Up to 2,000 items per run, longest-unchecked first
- **Choose how recent a release must be to get the upgrade window**
  - **Release Age** (default 7 days) sets which newly collected items go to the Upgrading queue, including items found by the local library scan. It was fixed at 7 days before

### Changed
- **All upgrade settings are on the Upgrade Hub**
  - A new **Upgrading** group on the hub's Settings tab holds turning upgrading on, the release age, the upgrade window, the score improvement needed, the score to stop at, the extra search after release, and removing the old copy
  - They're no longer on Settings → Scraping or Settings → Queues & Upgrades, which link to the hub instead. Your existing values are kept
- **Cache badges work beyond Real-Debrid**
  - TorBox users see whether a candidate is cached, from TorBox's own cache check. Real-Debrid still uses Phalanx
  - Badges read "Cached" / "Not Cached" for any service, and scraper finds show a "Live search" badge
  - Auto-queue queues cached candidates first and skips ones reported not cached, unless you accept uncached results
- **The Upgrading queue no longer holds up other queues**
  - It runs every 5 minutes and spends at most about 2 minutes searching per run; items it doesn't reach go first on the next run. Each item is still searched at most once an hour
  - Upgrades you queued from the Upgrade Hub go before ordinary searches
  - A long upgrade window or a big backlog used to keep a queue worker busy for the whole list
- **Scheduled Upgrade Hub scans run in the background**, so they don't delay other scheduled tasks

### Fixes
- **4K upgrades of the same release were skipped**
  - A result whose name was 95% similar to the current file was treated as the same file. "Movie.2025.1080p.WEB-DL-GROUP" and "Movie.2025.2160p.WEB-DL-GROUP" are 96% similar, so the 4K version was never picked
  - Now only the same torrent, or the same name once punctuation and the file extension are ignored, is skipped
- **Saving Settings could turn upgrading off**
  - The Settings page set upgrading to off whenever its checkbox wasn't on the page

### Behind the scenes
- **Scraper search** (`database/upgrade_hub_scrapers.py`)
  - Runs `ScrapingQueue.scrape_with_fallback` per item with 2 workers and scores results together with the current file through the same `_score_results_with_current` the Zilean phase uses, with the same episode, size and not-wanted filters
  - Last check times live in a new `upgrade_hub_scraper_checks` table (`item_id`, `checked_at`)
  - Results are merged with Zilean/NZB candidates per item, keeping the larger improvement
  - Gets the whole filtered library (genre and NAS exclusions, movie dedupe), not the Scan Limit slice
- **Search Recent Releases**
  - `POST /upgrade_hub/api/scan` takes an optional `recent_release_days` (0–3650). `scan_for_upgrades(recent_release_days=N)` limits the scraper phase to items whose `release_date` is 0–N days ago (`released_within()`), lifts the cap to `MAX_CHECKS_PER_SCAN` and runs the phase even with `use_scrapers` off. Zilean and NZB phases run as usual
  - `GET /upgrade_hub/api/recent_preview?days=N` returns the movie and episode counts for the confirm dialog (`count_recent_items()`; before the genre, NAS and duplicate-file filters)
- **Cache status**
  - `annotate_cache_status` asks TorBox's `checkcached` in batches of 50, or Phalanx for Real-Debrid. AllDebrid, Debrid-Link and Premiumize can only check by adding the torrent, so they stay unknown until queued
  - Candidates now carry `cached` / `cached_bypass` / `cache_service`; older saved scan results with `rd_cached` still display
- **Upgrading queue**
  - `PASS_BUDGET_SECONDS = 120` in `queues/upgrading_queue.py`; the task interval went from 3600 s to 300 s
  - `_pass_order()` sorts each run: hub-queued magnets, then never searched, then oldest `last_scrape_times`. A fixed order let the items at the front use the whole budget every hour, so the rest were never searched
  - `Debug.upgrade_queue_duration_hours` is read whether it's stored as text (old Settings page) or a number (Upgrade Hub)
  - `is_same_release()` replaces the `SequenceMatcher` ratio filter
- **Settings**
  - New `Scraping.upgrade_max_release_age_days` (default 7), read through `get_upgrade_max_release_age_days()` in `utilities/settings.py` by both `database/collected_items.py` and `utilities/local_library_scan.py`. The other moved keys keep their sections (`Scraping`, `Debug`), so there's no migration
  - New `Upgrade Hub.use_scrapers` (default on) and `Upgrade Hub.scraper_checks_per_scan` (default 50)
  - The hub's `/api/settings` reads and writes the upgrading keys in their own sections, with range checks
- **Tests**
  - `tests/queues/test_upgrades.py`: 32 tests covering Search Recent Releases (date window, cap and toggle, route checks), the same-release check, scan rotation (including with a Scan Limit), the scraper scan end to end with no other source, cache status per provider, the queue budget and run order, the upgrade window stored as text or number, Release Age in both collection paths and the settings round trip
