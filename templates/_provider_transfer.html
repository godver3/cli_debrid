Migrate between usenet providers

Moves the stored .nzb of each item from one usenet backend to the other; the target re-fetches it from usenet. No re-search, categories preserved where the source exposes them. cli-debrid runs in a container, so it reads NzbDAV over HTTP and cli_mount from a mounted path (no Docker needed).

Before you run this:
  • The target re-downloads from usenet — subject to your provider's retention & connection limits.
  • Best-effort: cli_mount trims old .nzb files, so part of an older library may not be transferable.
  • Avoid running it during a Plex scan on the same library (heavy concurrent activity).
  • Start with a small limit to test before transferring everything.
{# --- cli_mount fields --- #}

Path inside this cli-debrid container to cli_mount's stored .nzb files. Bind cli_mount's appdata into cli-debrid (the same data_path bind the cli_mount DB tools use) and point this at its usenet/nzbs folder. Example compose volume: - /host/cli_mount/appdata:/cli_mount_data → then this path is /cli_mount_data/usenet/nzbs.

{# --- NzbDAV fields --- #}

cli_mount's nzb-store is flat (no category), so transferred items land in this NzbDAV category. Must already exist in NzbDAV. To preserve categories, migrate one category at a time by pointing the path above at that category's releases.
