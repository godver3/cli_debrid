Migrate between usenet providers

Moves the stored .nzb of each item from one usenet backend to another; the target fetches it from usenet again. No re-search, and categories are kept where the source has them. Works with cli_mount, NzbDAV, Zurg (as a target only: it keeps no stored NZBs) and the built-in mount.

Before you run this:
  • The target re-downloads from usenet, so your provider's retention and connection limits apply.
  • Best-effort: cli_mount trims old .nzb files, so part of an older library may not be transferable.
  • Avoid running it during a Plex scan of the same library.
  • Start with a small limit to test before transferring everything.
{# --- source fields --- #}

Path inside this cli-debrid container to cli_mount's stored .nzb files. Bind cli_mount's appdata into cli-debrid (the same data_path bind the cli_mount DB tools use) and point this at its usenet/nzbs folder. Example compose volume: - /host/cli_mount/appdata:/climount_data → then this path is /climount_data/usenet/nzbs.

cli_mount stores NZBs under their IDs; its URL is used to look up the release names. Without it, names come from the NZB itself where the indexer wrote one.

Reads the NZBs from the built-in mount on this machine; nothing to fill in.

{# --- target fields --- #}

Used for items whose source has no category (cli_mount's store is flat). Must already exist on the target. To keep categories from cli_mount, migrate one category at a time.

Sends the NZBs to the built-in mount on this machine; nothing to fill in.

Next steps. The items now exist on the target, but cli_debrid still points at the old backend:
  1. Settings → Usenet Provider: switch to the new backend (URL, token, mount path).
  2. If the mount path changed, use Tools → Symlinks → Modify Symlink Base Paths (or update File Management's original files path), then Resync Symlinks.
  3. Check a few items play before removing anything from the old backend.
