Usenet Provider

Connect a usenet backend — cli_mount (custom API, default port 8888) or NzbDAV (SAB-compatible API, default port 3000). Both handle NNTP and serve files via the rclone mount.
{% set _provider = settings.get('Usenet Provider', {}).get('provider', 'climount') %}

Backend type. cli_mount uses custom endpoints (/api/add, /api/browse/nzbs); NzbDAV uses standard SAB query-string API (?mode=…). Both expose the same client interface internally.

How to set up NzbDAV (click to expand)

Two containers, one backend (same pattern as zurg + zurg_rclone): the nzbdav container is the downloader + WebDAV server; an rclone container mounts that WebDAV as a normal folder (e.g. /mnt/nzbdav) so Plex and cli-debrid can read the files as a path. You need both — cli_mount only looked simpler because it bundled the mount internally.

Don't write these by hand: use the setup helper below — it generates the docker-compose.yml (both containers) + rclone.conf + the config block for you, and can test the connection and create the required categories. The steps below are what it sets up:

  1. Deploy the NzbDAV stack (nzbdav + rclone) — copy the files from the setup helper below, then docker compose up -d.
  2. In NzbDAV: add your usenet (NNTP) provider + indexers, then copy the SAB API key (NzbDAV → Settings → API).
  3. Add the categories cli-debrid uses — NzbDAV → Settings → Categories: movies, shows, movies_1080p_264, shows_1080p_264, __unplayable__. Missing categories ⇒ grabs are rejected and loop in "Wanted".
  4. Fill the fields below: Provider URL (e.g. http://host:3000), API Token (the key from step 2), Download Folder = __unplayable__, NzbDAV Mount Path (where the rclone mount appears in this container, e.g. /mnt/nzbdav).
  5. Bind the mount + Plex: bind the nzbdav rclone mount into this container at that path, and add the content/movies, content/shows (+ _1080p_264) folders to your Plex libraries.
  6. Verify with the helper's Test connection & ensure categories button below, then toggle Enable Usenet above.

Switching from cli_mount? Just set Provider to NzbDAV and update the URL/Token here — your existing cli_mount files don't move. Run NzbDAV in parallel and let new grabs fill it (a hard mount-swap can make Plex purge "missing" items). To move existing downloads across, use Debug → Library → "Migrate between usenet providers" (in-app, both directions). For the cli_mount→NzbDAV direction it reads cli_mount's stored .nzb files, so bind cli_mount's appdata into cli-debrid (set cli_mount Data Path below) and the tool reads them from <data_path>/usenet/nzbs. (The host CLI nzbdav_setup.py migrate-files does the same from the shell.)

How to set up cli_mount (click to expand)
  1. Run cli_mount with its rclone mount; configure your usenet provider + indexers in cli_mount.
  2. Fill below: cli_mount URL (host:8888 — not localhost, conflicts with Phalanx DB), API Token (if auth enabled), Download Folder (leave empty for cli_mount's default).
  3. Set the cli_mount Data Path (bind cli_mount's appdata to /cli_mount_data) if you want backup/restore/cleanup tools.
  4. Toggle Enable Usenet above.

Do not use localhost:8888 — that conflicts with Phalanx DB. Use the cli_mount host IP or container name.

Use the NzbDAV host IP or container name with its port (default 3000), e.g. http://192.168.1.x:3000. Do not append /sabnzbd — NzbDAV serves its SAB-compatible API at the root /api.

Category/folder in cli_mount for downloads. Leave empty to use cli_mount's default download folder.

This is not a download destination — it's the fallback category used only if the per-release title heuristic can't classify a grab. In practice the heuristic classifies everything (it auto-routes to movies / shows / music and the *_1080p_264 variants), so this almost never fires. Recommended value: __unplayable__ — a category Plex doesn't scan, so any unclassifiable grab parks there harmlessly instead of polluting a library. This name (and every category the heuristic emits) must exist in NzbDAV's api.categories — use the setup helper's "ensure categories" button above, or add them in NzbDAV → Settings → Categories.

Path to cli_mount's data directory inside the container. Add - /path/to/cli_mount/appdata:/cli_mount_data to your docker-compose volumes, then set this to /cli_mount_data. Required for cli_mount DB backup, restore, and cleanup tools — and lets the in-app provider migration (Debug → Library) read cli_mount's stored .nzb files from <data_path>/usenet/nzbs.

Path inside this container where the NzbDAV rclone-mount appears. NzbDAV has no /browse API, so folder lookups walk the filesystem under <this path>/content/<category>/. Bind-mount the nzbdav-rclone mount into the cli-debrid container at this same path. A trailing /__all__ is stripped automatically (zurg-path compatibility). Effectively required when provider is NzbDAV.

Comma-separated NzbDAV categories the broken-NZB repair tool may act on. NzbDAV history is shared with other SAB clients (e.g. Lidarr music) — repair only re-acquires content cli-debrid manages, so it must never touch another app's entries. Leave empty to auto-pick the categories cli-debrid grabs into (plus the Download Folder fallback). Set only if your category names differ.

Comma-separated NzbDAV categories the repair tool must ignore (subtracted from the owned set). Use this if you point Radarr/Sonarr at the same NzbDAV and don't want cli-debrid touching their categories.

Maximum age of NZB results in days. Results older than this are filtered out at search time and never submitted to the Usenet provider. Set to 0 to disable. Applies everywhere NZB indexers are searched (queue, scraper results, upgrade hub, repair).

Reject NZB season packs entirely (movies are unaffected). A single damaged article in a season pack repairs the whole pack via a fresh grab; with this enabled, only aggregate/single-episode NZB results are considered, so a bad file only affects that one episode.
